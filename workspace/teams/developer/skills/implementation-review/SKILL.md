# Implementation Review

## Inputs
Task, target users, constraints, and acceptance criteria.

## Steps
1. Confirm requirements and identify missing information.
2. Design, implement, and verify the solution under team/project rules.
3. Do not use Thai text or emojis in code comments.
4. Split functions longer than 7 lines into smaller functions.
5. Move reusable logic into appropriate utils modules for use across classes.
6. Follow consistent naming conventions (camelCase, kebab-case, snake_case) appropriate to the language and project.
7. Use meaningful variable names, including loop variables.
8. Run the configured linter and available analyzers such as Semgrep or SonarLint. Report checks that could not run.

## Output
Summarize the solution, changes, verification results, and limitations.

## Acceptance
Meet the requirements, provide verifiable evidence, and never fabricate results.
