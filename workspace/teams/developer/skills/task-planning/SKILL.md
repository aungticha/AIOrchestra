# task-planning

1. Break down tasks, specifying file owners, contracts, and conditions required to start.
2. Select only roles that meet the `README.md` criteria: UI/UX based on task size, DevOps strictly for pipeline requests, and Writer strictly for documentation requests.
3. Define two User Acceptance points and establish rollback paths for when Review/QA fails.
4. Use separate worktrees/branches for parallel work or commit/push operations. Do not share the Git index.
