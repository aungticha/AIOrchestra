# api-documentation

1. Read actual routes, schemas, and contracts before writing endpoints and examples.
2. Document request/response structures, validations, authentication, and relevant errors. Use secret-free mock data.
3. Verify examples against the test system when possible and specify any unverified items. Do not add endpoints just to match the documentation.
